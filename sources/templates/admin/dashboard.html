How this works

  • Add dispatches the infra repo's GitHub Actions workflow, which writes the new client's UUID to Infisical and redeploys xray. "dispatched" means the trigger call succeeded; the "Workflow run" column reflects the actual run's status/outcome, refreshed each time this page loads — "success" means xray actually restarted with the new client.
  • Delete dispatches the matching removal workflow and blocks the client's site login immediately ("pending_removal"/"removing"); the row itself disappears once a page load confirms the removal run succeeded.
  • Edit — email/flow are editable in place ("Save") except while an add/edit/remove is already in flight for that client. Editing dispatches the matching update workflow and never revokes site login, unlike deleting.
  • Flow is xray's per-client VLESS flow control — pick "empty" if this client's own sing-box config enables multiplexing, since Vision (xtls-rprx-vision) and mux can't be combined.
  • Status/workflow-run columns refresh every 5s in place (no page reload) while any client has an add/remove/edit action in flight, so it never interrupts anything you're typing.
  • Save stays disabled until you actually change that row's email or flow.
  • Discord ID lets a Discord-authenticated visitor skip the site's own email+UUID login on repeat visits. It links itself automatically the first time someone logs in normally while Discord-authenticated — enter it here only to link it yourself ahead of time, e.g. for a client you already know the Discord account for.
