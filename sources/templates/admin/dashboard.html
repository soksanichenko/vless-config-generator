Adding a client dispatches the infra repo's GitHub Actions workflow, which writes the new client's UUID to Infisical and redeploys xray. "dispatched" means the trigger call succeeded; the "Workflow run" column reflects the actual run's status/outcome, refreshed each time this page loads — "success" means xray actually restarted with the new client. Deleting a client dispatches the matching removal workflow and blocks their site login immediately ("pending_removal"/"removing"); the row itself disappears once a page load confirms the removal run succeeded. "Flow" is xray's per-client VLESS flow control — pick "empty" if this client's own sing-box config enables multiplexing, since Vision (xtls-rprx-vision/-udp443) and mux can't be combined. Email/Flow are editable in place ("Save") except while an add/edit/remove is already in flight for that client; editing dispatches the matching update workflow and never revokes site login, unlike deleting. This page auto-refreshes every 5s while any client has an add/remove/edit action in flight.
